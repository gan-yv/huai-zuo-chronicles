# 新手 45 分钟 × 14 次开发计划

版本：0.1  
适用对象：Unity 新手、个人开发、每天约45分钟、使用 AI 辅助  
目标：从空目录推进到可以构建的扬州书坊核心灰盒  

## 1. 使用方式

这不是必须在14天内完成的日历承诺，而是一组连续工作时段。

如果某次没有完成，下一次继续同一目标，不跳步。

每次开始工作前，只需要告诉我：

```text
开始第 X 次
```

我会给出：

1. 本次唯一目标。
2. 三到五个具体步骤。
3. 需要复制的最小代码。
4. 如何验证是否成功。
5. 本次提交信息。

一次不要执行完整手册。只执行当前工作时段。

## 2. 每次45分钟的固定节奏

| 时间 | 内容 |
|---|---|
| 5分钟 | 打开项目，确认上次状态 |
| 25～30分钟 | 只完成一个可见小目标 |
| 5分钟 | 在 Unity 或构建版本中验证 |
| 5分钟 | Git 提交、记录卡点 |

不要用最后一个时段开启新系统。

## 3. AI 分工

### 我可以承担

- 写 Unity C# 脚本。
- 设计最简单的场景层级和组件接法。
- 生成对白、数据结构和测试用例。
- 检查 Git 状态和仓库文件。
- 根据报错信息定位问题。
- 给出下一步，不让用户同时面对太多选择。
- 生成 AI 美术提示词和素材整理规则。

### 需要你完成

- 在 Unity Hub 和 Editor 中点击操作。
- 发送报错、截图或当前界面描述。
- 运行游戏并判断是否顺畅。
- 决定对白是否符合你的想法。
- 最终确认美术是否具有扬州特征。

你不需要先学会 C# 才能开始。第一版代码会尽量短，并逐行解释。

## 4. 卡住时的规则

### 同一个问题超过10分钟

停止尝试，不要连续重装软件或乱改项目设置。

发送：

- 正在执行的步骤编号。
- 屏幕截图。
- 完整报错文本。
- 已经尝试过什么。

### 不确定点击哪里

直接说“我现在卡在第X次、第Y步”，并提供 Unity 界面截图。

### AI 生成的代码报错

不要自己猜着删除多行代码。复制完整 Console 报错，让我给最小修改。

### 每天结束时

即使没有完成目标，也要记录完成到哪一步。不要为了“必须完成”额外熬夜。

## 5. 第1次：本地 Git

目标：当前目录变成本地 Git 仓库并完成首次提交。

完成标准：

- `git status` 显示在 `main` 分支。
- 有一条 `docs: establish design and demo plan` 提交。
- `v0.0-design` 标签存在。

不安装 Unity 新内容，不写代码。

## 6. 第2次：私有 GitHub

目标：创建私有 GitHub 仓库并联通本地。

完成标准：

- 远程 `origin` 指向 `chunjiang-yiben`。
- `main` 已推送。
- 标签已推送。
- 网页能看到 README 和设计文档。

如果登录问题占用整个时段，本地提交仍然有效，下次继续。

## 7. 第3次：创建 Unity 工程

目标：创建一个最小 Unity 2D 工程。

具体方向：

- 使用 Unity 6000.5.7f1。
- 目录：`UnityProject`。
- 模板：2D Core。
- 不安装无关包。
- 保存一个空场景。

完成标准：

- Unity 能正常打开工程。
- `Assets/`、`Packages/`、`ProjectSettings/` 已提交。
- `Library/` 没有被提交。

## 8. 第4次：标题与开始按钮

目标：画面上出现游戏标题和“开始校对”按钮。

完成标准：

- 1920×1080 的游戏视图中文字清晰。
- 点击按钮会切换到书坊占位面板。
- 现在不需要正式背景。

## 9. 第5次：第一套对白

目标：在书坊占位场景里显示对白，并能点击继续。

完成标准：

- 显示说话人和正文。
- 连续点击可看到3句测试对白。
- 最后一句后出现一个按钮。

## 10. 第6次：修复室点击流程

目标：从标题进入修复室，点击残页进入异本。

完成标准：

- 修复室使用色块与文字占位。
- 残页可以被点击。
- 点击后出现一句确认对白，再切换到书坊。

## 11. 第7次：阶段验证与提交

目标：完整走一遍“标题 → 修复室 → 残页 → 书坊”，不新增系统。

完成标准：

- 流程可重复运行。
- 没有 Console 红色报错。
- 提交当前可运行版本。
- 打标签 `m0-unity-skeleton`。

## 12. 第8次：书坊两人物

目标：书坊出现陆掌柜和顾师父两个可点击对象。

完成标准：

- 两个对象都能点击。
- 点击后显示不同的一句提示。
- 点击只记录状态，不进入正式分支。

## 13. 第9次：调查二选一

目标：玩家只能选择调查其中一人。

完成标准：

- 两个人物按钮出现。
- 点击一人后，另一人的调查入口关闭。
- 状态分别记录为 `printer` 或 `performer`。

## 14. 第10次：调查结果

目标：根据选择显示不同的证词与证物名称。

完成标准：

- 陆掌柜分支显示节目册印样。
- 顾师父分支显示旧唱词页。
- 两条分支都能继续到下一步。

## 15. 第11次：异文比对界面

目标：显示“待”和“照”的双页文本。

完成标准：

- 左右两版文本都可见。
- 两个关键字高亮。
- 玩家可以点击一个候选字。
- 此时还不执行最终结果。

## 16. 第12次：确认、结果与校勘笺

目标：选择异文后二次确认，显示对应结果，并把选择写入校勘笺。

完成标准：

- 确认前可以取消。
- “待”和“照”分别进入不同结果文本。
- 两条结果都能进入校勘笺。
- 校勘笺显示异文、调查来源、传播方式和未解信息。
- 玩家可以从校勘笺进入结束卡。

## 17. 第13次：重新开始与状态清理

目标：结束卡可以完整重开。

完成标准：

- 重开后回到标题。
- 调查选择和异文选择被清空。
- 校勘笺文字、证词来源和未解记录被清空。
- 连续重开两次不会残留上一轮文本或按钮状态。

## 18. 第14次：Windows 测试构建

目标：离开 Unity Editor，运行独立测试版。

完成标准：

- 构建 Windows 64 位版本。
- 在资源管理器中直接启动。
- 从标题走到结束卡。
- 记录至少三个体验问题。
- 将构建排除在 Git 之外。

## 19. 14次后如何处理

### 如果核心流程成立

- 开始替换正式背景、人物和UI。
- 进行3～5人试玩。
- 再扩展为8～12分钟 Demo。

### 如果流程很无聊

不要加入更多美术和剧情。先修改以下最少的一项：

- 两个人物的理由是否都可信。
- 玩家是否过早知道“正确答案”。
- 异文比对是否只是读文字，还是有可操作内容。
- 选择后果是否足够快、足够明显。

### 如果每次45分钟压力过大

把一次计划拆成两次：

- 第一次只完成界面与占位。
- 第二次只接逻辑与验证。

不改变整体先后顺序。
