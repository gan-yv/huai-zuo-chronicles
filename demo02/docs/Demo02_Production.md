# 《Demo02》广陵 Demo 制作文档

版本：1.0
更新：2026-11-20
状态：当前制作基线
目标：制作一个可用于求职展示的广陵垂直切片
目标时长：15～20 分钟
工作标题：旧街回潮

本文合并了原“单 Demo 生产路线、广陵 Demo 规格、Git 协作流程”。长期设定以 [Demo02_Design_Bible.md](Demo02_Design_Bible.md) 为准。

## 1. 当前范围

本轮只实现：

- 一个 3D URP Unity 工程。
- 广陵城内的官署前街、盐仓横街、回潮巷和旧仓后巷。
- 主角与途印伙伴两名可操控角色。
- 一场可升级为巡逻队支援的街道战斗。
- 一次时空修复和一次有持久影响的关键选择。
- 两个可验证的街道结果状态。
- 从开始到结束的流程、基础 UI 和 Windows 构建。

本轮不实现：

- 海陵、通州、终章或其他可探索城市。
- 七道残世印的完整技能组。
- 等级、装备、词条、抽卡和开放世界刷取。
- 大规模人群、载具、复杂天气和完整昼夜循环。
- 多周目、大量结局或持续运营功能。

移动、战斗、修复和对话原型都属于同一个项目，不另立“第二个 Demo”。

## 2. 玩家体验目标

Demo 需要用一片有限街区证明以下内容可以组成完整体验：

- 3D 城市探索与街区小故事。
- 时空修复作为主线玩法。
- 残世印实时战斗与角色切换。
- 主角通过人物关系获得第一个续式。
- 玩家选择会持久改变街道状态。
- 广陵“正统与秩序”的主题落到具体人物和事件上。

Demo 不需要解释全部世界真相，只需让玩家理解：世界存在被覆盖的历史、隐藏的破坏者和一条更大的主线。

## 3. 核心事件

广陵官方地图上不存在的一条旧街在黄昏后重新出现。旧街居民认为自己一直生活在那里，但他们的姓名、屋契和店铺记录已经全部从现存档案中消失。

主角的受损修复工具捕捉到旧街内部的时缝信号，并发现一名溯世会成员正在加剧新旧街区的覆盖。官府准备封死旧街，盐商则试图从旧街仓库取走一份能改变地契归属的账册。

异常来自广陵主时锚“名籍”的失稳。主角必须在旧街彻底被覆盖前完成修复，并决定让哪一层历史保持稳定。

## 4. 主要角色

| 角色 | 立场与作用 |
|---|---|
| 主角 | 来自异世界的时空修复者。只有基础战斗能力，寻求修复工具和回家线索，不愿轻易相信任何势力 |
| 途印伙伴（姓名待定） | 熟悉广陵街巷的本地向导。了解普通人如何在官府和商帮之间生活，共同行动后帮助主角获得“途·折行” |
| 官府巡官 | 代表官方历史，首要目标是封锁异常、维持秩序；可以强硬、务实或同情居民，但核心立场是稳定优先 |
| 盐商账房 | 想取得旧地契或账册。证据既可能证明盐商早已拥有土地，也可能证明官府删除了旧街记录 |
| 旧街居民 | 被另一段时间层覆盖的真实居民，不是幻觉。封存旧街会让他们从城市记录和生活中消失 |
| 溯世会执行者 | 使用蚀印扩大旧街与现城的接缝。战败后逃入更深处，留下通往主时锚和溯世会的线索 |

## 5. 地图

| 区域 | 功能 | 主要内容 |
|---|---|---|
| 官署前街 | 教学区 | 介绍官府、巡官、修复工具和基础移动；黄昏钟声后看见旧街从巷口浮现 |
| 盐仓横街 | 社会调查区 | 与账房、搬运工、守卫和居民交谈，取得旧地契、搬运记录和失踪街名证词 |
| 回潮巷 | 时空异常核心 | 新旧建筑、招牌、行人和声音重叠；使用修复工具辨别时间层 |
| 旧仓后巷 | 战斗与攀行支路 | 获得“途·折行”后可到达高台和侧门；最终时缝接点位于尽头 |

## 6. 流程

### 第一阶段：辨层

- 使用修复工具观察同一地点的新旧时间层。
- 看见旧招牌、被涂改的姓名、不同年代的货物和居民残影。
- 找到三个关键接点，但不必让所有接点选择相同结果。

### 第二阶段：调查

- 在官署前街听取官方解释。
- 在盐仓横街取得商帮证据。
- 在回潮巷与居民接触，得知他们不知道自己在官方记录中已经消失。
- 玩家至少取得两类信息，才能判断修复的代价。

### 第三阶段：定接与合层

- 到达旧仓后巷后，主角尝试重新接合时缝。
- 三个接点分别连接官府、商帮和旧街居民。
- 修复不是简单清空异常，而是选择哪一层成为主要现实，以及另一层受到多大程度的压制。
- 修复不能倒转时间，只能稳定当前结果。

## 7. 核心玩法

### 第一个续式：途·折行

- 获取方式：与途印伙伴共同完成一次追查或救援，不通过击杀获得。
- 战斗用途：短距离快速位移，穿过敌人身侧或避开短枪射击。
- 探索用途：抵达高台、跨越临时缺口或从侧门进入旧仓。
- 限制：有冷却，不能连续穿过多个障碍，也不能替代修复工具。
- 范围：Demo 只展示这一个续式，但保留“最多同时装备两个续式”的框架。

### 战斗

Demo 安排一场主要街道战斗：

- 两名持冷兵器的守卫或打手。
- 一名持初级短枪的敌人。
- 枪声或玩家触发警戒后，相邻街道最多再加入两名巡逻兵。
- 溯世会执行者使用蚀印削弱视线、隐匿身影或腐蚀局部空间。
- 玩家可切换主角与途印伙伴，利用位移、近战、短枪威胁和环境掩体。
- 场景提供墙角、货箱、低矮屋顶和一个可绕后的侧门。
- 战斗目标是保护线索、突破封锁或救出居民，不以清空敌人为唯一胜利条件。
- 战斗结束后可继续移动或撤离，不进入独立结算空间。

### 时间层与修复锚点

- 玩家按 `Q` 在“现世”和“旧时”之间切换。
- 不同时间层显示不同的场景物件和可交互锚点。
- 集齐三条线索并清除巡逻队后，玩家需要稳定三个时间锚点。
- 当前灰盒中两个锚点位于现世，一个位于旧时，玩家必须切换时间层才能完成收集。
- 三个锚点全部稳定后，街尾修复接点才允许继续交互。
- 时间层切换只改变当前可见和可交互的世界层，不撤销已经收集的记录或已经发生的选择。

## 8. 关键选择

### 保住旧街

- 旧街居民和建筑进入当前城市，成为官方地图承认的新街。
- 官府权威受到挑战。
- 盐商获得一张可争夺地权的旧账。
- 巡官与商帮关系恶化，旧街开放但周边巡逻增加。
- 主角保留失踪街名的记录，后续更容易获得民间信任。

### 封存旧街

- 官署前街恢复稳定，旧街居民从现存记录中消失。
- 官府继续维持正统历史。
- 巡官可能提供通行或情报作为回报。
- 盐商失去旧账，但主角获得官府信任。
- 旧街被新的围墙或封锁线替代，玩家能直接看到后果。

两条路线都必须留下“溯世会存在”和“更大时缝正在扩张”的证据，保证主线可以继续。

## 9. 短故事与结束状态

Demo 只需两到三个短故事补充世界：

- 一名居民坚持自己的店铺昨天还在旧街，希望主角找回招牌。
- 一名盐仓搬运工知道货物被偷运，却害怕失去工作。
- 一名官府小吏发现父亲的名字出现在旧街记录里，却不敢承认。

这些故事分别展示居民、商帮和官府立场，不增加新的主要玩法。

Demo 结束时：

- 主角的修复工具恢复一部分功能。
- 主角获得第一个续式。
- 玩家已经体验两种残世印能力和一次角色切换。
- 旧街被保留或封存，地图发生持久变化。
- 溯世会执行者留下通往广陵主时锚“名籍”的线索。
- 主角明确下一项目标：追查主时锚。

当前灰盒操作：

```text
WASD 移动
Shift 奔跑
Space 跳跃
鼠标左键 近战攻击
按住鼠标右键 旋转镜头
E 调查、稳定锚点或修复
Q 切换现世/旧时
Tab 切换出场角色
R 在结局或队伍倒下后重开
```

## 10. 制作顺序

### 阶段 0：干净工程

交付：

- 3D URP 工程、基础场景、输入配置、版本控制分支和构建设置。
- 确认旧 2D 灰盒不再继续扩展。

完成标准：

- 3D 场景可启动、保存、重新打开并构建 Windows 版本。
- 输入系统在编辑器和构建中都能工作。

### 阶段 1：移动与镜头

交付：

- 第三人称移动、奔跑、转向、跳跃和镜头旋转。
- 四条街区的灰盒、碰撞、台阶、坡道和镜头防穿墙。

完成标准：

- 用占位胶囊走完整路线不卡住。
- 镜头在狭窄街巷中不频繁穿墙或失控。
- 新玩家能在 2 分钟内理解移动方式。

### 阶段 2：交互与街区故事

交付：

- 调查点、拾取线索、NPC 对话和任务提示。
- 官署前街与盐仓横街的基础内容。
- 简单的信息记录界面。

完成标准：

- 玩家能与至少四名 NPC 对话并取得两类线索。
- 对话结束后任务状态正确保存。
- 不依赖复杂过场也能理解目标。

### 阶段 3：时空修复

交付：

- 回潮巷的新旧时间层切换表现。
- 辨层、接点激活和合层交互。
- 一个用占位效果完成的三接点修复流程。

完成标准：

- 修复与战斗操作明确分离。
- 玩家能判断自己正在修复哪一层历史。
- 修复完成后场景状态会切换。

### 阶段 4：实时战斗

交付：

- 主角基础攻击、闪避、技能和大招占位实现。
- 两类敌人的巡逻、警戒、追击、支援、受伤、失败和脱战。

完成标准：

- 不封路、不切战斗场景。
- 敌人可以从相邻街道加入战斗。
- 玩家能够撤离，也能通过战斗打开通路。

### 阶段 5：伙伴与续式

交付：

- 途印伙伴加入队伍和战斗中角色切换。
- 通过剧情获得“途·折行”。
- 一个只能借助该续式到达的探索点。

完成标准：

- 切换角色有明确收益。
- 续式同时服务战斗和探索。
- 续式不替代修复工具。

### 阶段 6：完整垂直切片

交付：

- 从开场到旧街选择、街景变化和结尾钩子的完整流程。
- 两条结果路线共用大部分场景资源。
- 所有关键任务状态和地图变化。

完成标准：

- 20 分钟内可以从头玩到结束并重新开始。
- 没有阻断流程的缺失资源或未实现按钮。
- 玩家能用自己的话复述事件和主角目标。

### 阶段 7：内容与表现

交付：

- 角色占位形象、统一材质、基础动画、音效与音乐。
- 正式对话、UI、任务提示和战斗反馈。
- 完整中文校对和至少一轮外部试玩。

完成标准：

- 新玩家能理解核心操作、任务目标和选择后果。
- 画面、声音和 UI 形成统一风格。
- 试玩发现的阻断问题全部修复。

### 阶段 8：作品集打包

交付：

- Windows 可运行构建。
- 60～90 秒玩法视频。
- 一页设计说明。
- 试玩记录、已知问题和下一阶段计划。

完成标准：

- 招聘者无人讲解也能启动并完成 Demo。
- 作品集能说明个人贡献、设计取舍和迭代过程。

## 11. Unity 内容组织

工程建立后，Demo02 内容统一放在 `Assets/Demo02/`：

```text
Assets/
├─ Demo02/
│  ├─ Art/
│  ├─ Audio/
│  ├─ Data/
│  ├─ Prefabs/
│  ├─ Scenes/
│  ├─ Scripts/
│  ├─ Settings/
│  ├─ Tests/
│  └─ UI/
└─ ThirdParty/
```

规则：

- 每个脚本、预制体和场景只承担一个明确职责。
- 灰盒验证通过前不制作正式美术。
- 临时测试场景不留在最终构建列表中。
- 旧 Demo01 的场景、脚本和构建不迁入 Demo02 工程。
- 子目录职责和文件命名见 [Demo02 资源目录说明](../UnityProject/Assets/Demo02/README.md)。

## 12. 范围控制

每个阶段只选一项交付，按以下顺序推进：

1. 做最小可运行版本。
2. 自己测试并记录问题。
3. 修复阻断问题。
4. 通过完成标准后再进入下一阶段。

新增设定或功能前必须回答：

- 它是否属于当前广陵 Demo 的必要内容？
- 它会改变已有阶段顺序吗？
- 如果不做，Demo 是否仍能完整结束？

前两项任何一项为“否”，或第三项为“是”，就放入长期清单，不进入当前开发。

## 13. 下一项任务

创建干净的 3D 工程与广陵灰盒，只实现移动、镜头和街道碰撞。不要先做战斗、正式角色模型或完整剧情对白。

工程、分支和提交规则见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 14. 暂不制作

- 海陵、通州和终章地图。
- 完整七道残世印能力池。
- 装备、等级、随机词条和开放世界刷取。
- 多结局长分支。
- 大型人群模拟。
- 超出演示需要的支线和小游戏。
