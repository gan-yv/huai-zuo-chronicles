# 存档与输入规范

## 输入

运行时代码只通过 `Demo02Input` 读取输入。该服务维护 `Gameplay` 和 `UI` 两张
Input Action Map，统一处理键盘、鼠标与手柄绑定，并暴露菜单导航、提交、取消和
玩法动作。不要在控制器中直接读取 `Keyboard.current`、`Mouse.current` 或
`Gamepad.current`。

重新绑定使用 `Demo02Input.TryRebind`，覆盖项保存在 `PlayerPrefs`。设置界面可
选择常用动作并重新绑定；恢复默认设置会同时清除输入覆盖项。

弹窗、对话、地图、案卷、背包、设置或存档界面打开时，玩法动作会在读取层统一
失效，UI 动作保持可用。对话推进使用独立的 `Advance` 动作，选项使用
`Choice1`、`Choice2`，避免借用队伍切换等玩法动作。

输入服务记录最后使用的键鼠或手柄，并通过 `GetPreferredBindingDisplay` 选择
对应设备的显示文本。交互和对话提示不再假定固定键位；新增提示应使用动作显示
文本或 `Demo02Input.ResolvePrompt`，不要再次直接写死 `E`、`Space` 等键名。

## 存档

新存档使用带 `SaveVersion`、`Checksum` 和 `Payload` 的信封格式。校验和覆盖
完整 payload。`SaveDataMigration` 按版本逐级升级，稳定 ID 重命名应在对应版本
步骤中增加别名迁移。

写入时先生成并验证临时文件，同时保留上一份有效 `.bak`。主文件损坏时自动读取
备份，并以当前格式重写主文件。未知的更高版本不会被静默读取。

当前存档版本为 3。战斗单位使用场景作用域 `PersistentId` 保存和恢复；对象名
只作为版本 2 存档与诊断兼容字段，新内容必须配置稳定 ID。自动存档使用每秒
一次的状态签名检查，状态连续稳定 2 秒后才写入，且两次自动存档至少间隔 8 秒。
签名包含真实线索、事实、锚点、项目进度和战斗单位 ID/生命，不依赖集合数量。

章节阶段恢复优先信任存档阶段，只在旧存档缺少信息或阶段明显早于已取得进度时
向前推导。`RepairRift`、`FinalDecision` 等阶段不得因锚点集合非空而回退。
